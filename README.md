# KBO Weather Forecast — 구장 핀포인트 기상 브리핑

KBO 1군·퓨처스리그 **오늘 경기 전부**에 대해, 구장 좌표 기준으로

1. **우천 취소 / 중단 확률** — 212개 앙상블 멤버를 각각 "시나리오"로 보고 경기 시간창(시작 1시간 전 ~ 종료)에 대해 계산
2. **타구 비거리 지수** — 표준 타구(100 mph · 28° · 1800 rpm)를 오늘 공기밀도·구장 방향 바람으로 물리 시뮬레이션해 표준 대기 대비 ±m 로 표시, 홈런 기대 배수
3. **폭염 판정** — 기상청 여름철 체감온도 산출식 + KBO 2026-08 폭염 취소 규정 구간

을 매일 자동 생성합니다. **외부 패키지 0개, 운영비 0원** (Python 3.11+ 표준 라이브러리만). 키 없이도 돌고, 기상청 무료 키를 넣으면 기상청 예보가 함께 섞입니다.

```bash
python3 -m kboweather today                 # 오늘 1군+퓨처스 전 경기 → out/YYYY-MM-DD.{md,html,json}
python3 -m kboweather today --league 1      # 1군만
python3 -m kboweather date 2026-09-13       # 다른 날짜 (forecast_days 안이면 됨)
python3 -m kboweather venue 잠실 --at 2026-09-13T17:00   # 경기 없어도 임의 조회
python3 -m kboweather stadiums              # 구장 DB 확인
python3 -m kboweather backtest              # 시즌 우천취소 실적 대조 (임계값 검증)
python3 -m kboweather verify                # 기상청 vs 앙상블 vs 최종 예측 채점 (기록이 쌓이면)
```

옵션: `--telegram` (봇 전송) · `--narrate` (Ollama 로컬 LLM 캐스터 멘트) · `--speak` (macOS `say`로 음성 파일).

## 계산 방법

### 강수 (`kboweather/rain.py`)
앙상블 멤버 하나 = 자기 일관성 있는 날씨 시나리오 하나. 각 멤버에 대해

| 창 | 범위 | 뜻 |
|---|---|---|
| `pre` | 시작 −7h ~ −1h | 그라운드 사정 (사전 누적) |
| `game` | 시작 −1h ~ +3.5h | 경기 중 비 |
| `early` | 시작 ~ +2h | 5회(정식 경기) 전 강한 비 |

를 누적한 뒤 리그별 임계값으로 `rain / delay / cancel / ground` 이벤트 분류. 확률 = 시스템별 멤버 비율의 평균(ECMWF 51멤버가 UKMO 18멤버를 압도하지 않도록 시스템 동등 가중) 75 % + 결정론 모델 동의 비율 25 %.

**기상청 섞기** (`kma_service_key` 있을 때): 경기 시간 중 가장 높은 기상청 시간별 강수확률을 기상청이 보는 '경기 중 비' 확률로 삼고(기상청 강수확률은 시간끼리 강하게 묶여 있어 시간별 확률을 더하면 과대평가됨) 경기 6시간 이내 50 %, 24시간 이내 35 %, 그 이상 25 % 비중으로 섞습니다. 중단·취소는 기상청 예상 강수량이 기준을 넘을 때만 그 확률을 씁니다. 가중치는 가정값이라, 매 실행 결과를 `data/history/forecasts.jsonl` 에 쌓고 `python3 -m kboweather verify` 가 기상청·앙상블·최종 예측을 실제 취소 결과로 채점합니다.

임계값은 사전 지식으로 정한 뒤 `backtest` 로 **2026 시즌 실제 취소 결정과 대조**했습니다 (정규경기 1,316건, 우천·그라운드 취소 140건, 당시 발표된 예보 아카이브 사용). 퓨처스는 1군보다 쉽게 취소되므로 더 민감한 값, 인조잔디 구장은 사전 누적 임계값을 1.3배로 완화.

| 예측 취소 확률 | 1군 경기 수 | 1군 실제 취소율 | 퓨처스 경기 수 | 퓨처스 실제 취소율 |
|---|---|---|---|---|
| 0–10 % | 591 | 1.2 % | 570 | 7.2 % |
| 10–30 % | 12 | 16.7 % | 26 | 34.6 % |
| 30–50 % | 16 | 25.0 % | 12 | 33.3 % |
| 50–70 % | 22 | 54.5 % | 23 | 82.6 % |
| 70–100 % | 17 | 88.2 % | 27 | 100 % |

Brier 점수 1군 0.029 (기후값 0.057), 퓨처스 0.077 (기후값 0.129). 1군은 prior 그대로가 거의 최적이었고, 퓨처스는 그리드 탐색값(`cancel_rate 3.0`, `wet_pre 6 mm`)을 채택했습니다. 퓨처스 저확률 구간(7.2 %)이 높은 이유: 그라운드사정 취소 34건 중 상당수가 전날 밤 비 때문인데 현재 사전 창은 시작 7시간 전까지만 봄 → 다음 개선 항목.

### 비거리 (`kboweather/physics.py`)
- 습윤 공기밀도 ρ(기온, 현지 기압, 습도) — 습도가 높을수록 오히려 가벼움
- Alan Nathan 궤적 계산기와 같은 항력/양력 계수(Cd = 0.3008 + 0.0292·rpm/1000, Cl = 1.12S/(0.583+2.333S)), RK4 적분
- 표준 대기(20 ℃·1013.25 hPa·50 %·무풍)에서 124.8 m 인 타구가 오늘 조건에서 몇 m 인지 → Δ
- 바람은 10 m 풍향을 **구장 외야 방위각**(중앙·좌·우 ±45°) 기준으로 순풍/측풍 분해. 관중석에 둘러싸인 구장은 실제로 바람이 줄어들므로 `shelter` 계수(1군 0.5~0.55, 개방형 2군 0.85, 돔 0) 적용 — 이 계수는 가정값이므로 리포트에 명시
- 홈런 기대 배수: 비거리 +1 % ≈ 홈런 +6 % (Nathan 경험식)

### 폭염 (`kboweather/heat.py`)
기상청 2022 여름철 체감온도 = f(기온, Stull 습구온도). KBO 2026-08 개정 기준: 체감 35 ℃↑ 취소 가능(당일 13시 결정), 33 ℃↑ 쿨링브레이크·최대 1시간 지연. 임계값은 `LEVELS` 에 있어 규정이 바뀌면 한 줄 수정.

## 자동화

| 방법 | 파일 | 비용 |
|---|---|---|
| 1순위: 맥에서 매일 08:30·15:30 | `scripts/com.woo.kboweather.plist` → `~/Library/LaunchAgents/` (`scripts/run_auto.sh` 실행) | 0 |
| 백업: GitHub Actions 10:00·16:15 | `.github/workflows/daily.yml` (Secrets 에 `KMA_SERVICE_KEY`, 선택 텔레그램) | 0 (private 저장소 무료 월 2,000분 중 월 수십 분) |
| 텔레그램 | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (또는 `config.toml`) | 0 |
| 캐스터 멘트 | `--narrate` → Ollama `gemma4:12b` (또는 `exaone3.5:2.4b`) | 0 (로컬) |
| 음성 | `--speak` → `say -v Yuna` → `out/…-brief.m4a` | 0 |

**맥과 GitHub 이 겹치지 않는 방법** (`python3 -m kboweather auto`): 하루를 오전(06–15시)·오후(15–21시) 두 시간대로 나누고, 먼저 돈 쪽이 `data/runs/날짜-am|pm.json` 표시 파일을 커밋합니다. 맥은 실행 전에 `git pull` 로, GitHub 은 체크아웃으로 이 파일을 보고 이미 있으면 건너뜁니다. 그래서 텔레그램은 한 번만 오고, 예보 기록(`data/history/`)과 리포트(`out/*.html·md`)는 저장소 한곳에 모입니다. 맥이 잠든 시각의 실행은 깨어날 때 한 번 돌지만 그 사이 GitHub 이 돌렸으면 건너뜁니다. 로컬 기록은 `out/auto.log`. GitHub 서버는 해외에 있어 기상청 API가 막히면 기상청 없이 계산하고 카드에 그렇게 표시합니다. 로컬 푸시가 매일 일어나므로 "60일 무활동 시 예약 워크플로 중지" 규칙에도 걸리지 않습니다.

API 호출량: 구장당 2회(결정론+앙상블) × 하루 ≤ 15구장 × 2회 실행 ≈ 60회/일 (앙상블은 강수 1개 변수만 요청해 무게를 줄임). Open-Meteo 무료 한도는 분당 600 · 시간당 5,000 · 하루 10,000회. 짧은 시간에 몰아 호출해 429(한도 초과)를 받으면 30초·60초 기다렸다 재시도하고, 그래도 앙상블을 못 받으면 해당 경기는 고해상도 모델 7개만으로 판단합니다(카드에 명시).

## 출력

- `out/YYYY-MM-DD.md` — 텔레그램/콘솔용 요약
- `out/YYYY-MM-DD.html` — 1군(기본)·퓨처스 탭 대시보드. 경기마다 서술형 '예보 근거 읽기'와 시간대별 표, 다크모드 대응. 주소 끝에 `#futures` 를 붙이면 퓨처스 탭으로 열림
- `out/YYYY-MM-DD.json` — 전체 수치 (시나리오별 확률, 모델별 강수, 비거리 시뮬레이션 상세)
- `out/backtest-*.json` — 백테스트 원자료

## 한계와 다음 단계

- **임계값 보정**: 우천취소는 '예보'로 결정되므로 과거 예보 아카이브 대조가 맞는 방법이지만, 결정론 모델만 아카이브되어 앙상블 확률은 시즌이 지나며 `out/*.json` + KBO 사유로 직접 검증하는 게 정확함 (매일 돌리면 자동 축적)
- **shelter 계수**는 문헌값이 없어 가정. 구장별 실측(경기 중 관측 vs 모델)으로 조정 여지
- **방위각 ±10°**: 위성 판독. 정밀값이 필요하면 `data/stadiums.json` 만 고치면 됨
- 기상청 LDAPS 복구 시 1.5 km 해상도 모델이 자동으로 합류 — `kboweather/openmeteo.py` 의 `DET_MODELS` 참조
- KBO 폭염 규정은 2026-08 임시 개정 기준 — 시즌 개막 때 `heat.LEVELS` 확인
